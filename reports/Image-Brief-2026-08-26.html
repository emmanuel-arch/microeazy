The apex

4 NEW · microeazy.servicesuitecloud.com

The right half of the customer sign-in screen. Warm, human, documentary — the opposite register to the suite, deliberately. These are the people who actually borrow here, and the panel is currently a flat gradient waiting for them.

The composition rule, and why it differs from the suite's

On the staff doors the sign-in card sits on the artwork, so those plates keep their left third empty. Here the card has its own column and the photograph owns a full half — but the slider's headline is centred over it.

So: keep the centre calm. Subject to one side, or far enough back that a two-line heading can cross the middle without landing on a face. Every prompt below already says this; do not drop it.

One more, and it is the one that matters most: dark skin must be rendered with real warmth and detail in the shadows. Image models routinely grey it out or crush it. Reject any frame where it reads ashy.

Why the encode step is not optional

The suite plates arrived as ~1.5 MB PNGs and the set totalled 8.02 MB. PNG is the wrong container for a photograph, and these load before anything else on a sign-in page. Re-encoded to WebP the same set is 230 kB — 97% smaller, with nothing visible lost through the scrim the card sits on. Keep the PNGs on disk as masters; the code reads the .webp.

npm run art:prompts # print the suite prompts, paste-ready npm run art:optimize # dry run — report what the encode would do npm run art:optimize -- --write # encode

One thing to fix on Micromart's side, not ours

Entity 3005 (MICROMART FINTECH) — the entity both the app and the staff suite now read — has an empty branding row: primaryColor and secondaryColor both return #000000, and ggDriveFolder returns the string "Failed". Those are values rather than absences, so a naive fallback paints a black-on-black interface.

The app guards against it and falls back to Micro Eazy navy, which is why the sign-in screen looks right today. But it is not Micromart's brand. Ask them to fill that row in and the real colours apply everywhere with no code change — the guard stops matching on its own.
